# `data/`

Generated by `python -m quran_etl`. Do not edit JSON files by hand.

This single tree contains two paired editions of the same Arabic Quran dataset:

| Edition | Item files | Indexes | Format |
|---|---|---|---|
| Full | `001.json` | `index.json` | Descriptive keys, indented, complete metadata |
| Minified | `001.min.json` | `index.min.json` | Short keys, compact JSON, lower token usage |

Every range-bearing file is self-contained and embeds its complete ayah list. Sajdah files embed their single referenced ayah.

## Layout

```text
data/
├── README.md
├── index.json
├── index.min.json
├── quran.full.json
├── quran.full.min.json
├── surah/{001..114}[.min].json
├── ayah/{001_001..114_006}[.min].json
├── juz/{01..30}[.min].json
├── manzil/{01..07}[.min].json
├── hizb/{01..60}[.min].json
├── rub/{001..240}[.min].json
├── ruku/{001..556}[.min].json
├── page/{001..604}[.min].json
└── sajdah/{01..15}[.min].json
```

Per-ayah filenames use `_` instead of `:` because Windows forbids `:` in filenames. Quran keys inside JSON retain the `1:1` form.

## Loading examples

```python
import json
from pathlib import Path

DATA = Path("data")

full_ayah = json.loads((DATA / "ayah" / "002_255.json").read_text(encoding="utf-8"))
min_ayah = json.loads((DATA / "ayah" / "002_255.min.json").read_text(encoding="utf-8"))
full_juz = json.loads((DATA / "juz" / "01.json").read_text(encoding="utf-8"))
min_juz = json.loads((DATA / "juz" / "01.min.json").read_text(encoding="utf-8"))
```

The full and minified models, indexes, and unified files are documented in [`docs/SCHEMA.md`](../docs/SCHEMA.md) and have machine-readable JSON Schema 2020-12 documents under [`docs/json-schema/`](../docs/json-schema/).

## Minified key map

### Ayah

| Full | Minified | Meaning |
|---|---|---|
| `key` | `k` | `"<sura>:<aya>"` |
| `text` | `t` | Normalized Uthmani Arabic text |
| `text_clean` | `tc` | Text with diacritics and marks removed |
| `sajda` | `sj` | `null`, `"o"`, or `"r"` |
| `page` | `p` | Mushaf page number |
| `parents` | `ps` | Parent map using short scope codes |

The minified Ayah omits `id`, `sura`, `aya`, `global_id`, `text_raw`, `char_count`, and `word_count`.

### Surah

| Full | Minified |
|---|---|
| `id` | `i` |
| `key` | `k` |
| `name_arabic` | `na` |
| `name_transliteration` | `nt` |
| `name_english` | `ne` |
| `revelation_type` | `rt` |
| `ayah_count` | `ac` |
| `ruku_count` | `rc` |
| `start_ayah` | `sa` |
| `end_ayah` | `ea` |
| `ayahs` | `a` |

The minified Surah omits `revelation_order`, `bismillah_pretext`, `ayah_ids`, `parent_ids`, and `child_ids`.

### Range scopes

Juz, manzil, hizb, rub, ruku, and page share these keys:

| Full | Minified |
|---|---|
| `id` | `i` |
| `key` | `k` |
| `start_ayah` | `sa` |
| `end_ayah` | `ea` |
| `ayah_count` | `ac` |
| `ayahs` | `a` |

Scope-specific minified keys are `sc` for `surahs_covered`, `sh` for `surah`, `ji` for `juz_id`, and `hi` for `hizb_id`.

### Sajdah

| Full | Minified |
|---|---|
| `id` | `i` |
| `key` | `k` |
| `ayah` | `ay` |
| `type` | `t` |
| `surah` | `sh` |
| `ayah_data` | `ad` |

Sajdah type uses `"o"` for obligatory and `"r"` for recommended.

### Parent codes

| Code | Scope |
|---|---|
| `s` | surah |
| `j` | juz |
| `m` | manzil |
| `r` | ruku |
| `h` | hizb |
| `q` | rub |
| `p` | page |

### Unified minified file

`quran.full.min.json` uses these top-level keys:

| Key | Meaning |
|---|---|
| `m` | Metadata |
| `s` | Surahs |
| `j` | Juz |
| `mn` | Manzil |
| `rk` | Ruku |
| `hz` | Hizb |
| `rb` | Rub |
| `pg` | Pages |
| `sj` | Sajdah |

Metadata uses `src`, `tt`, `ac`, `sc`, `jc`, `mnc`, `rc`, `hc`, `rbc`, `pc`, `sac`, `ga`, `sv`, and `sp`. Both editions use dataset contract version 4.

## Building

```bash
python -m quran_etl --verify
python -m quran_etl --min --verify
python -m quran_etl --min --clean --verify
python -m quran_etl --min-only --verify
```

`--clean` removes only the selected generated JSON variants and preserves this documentation.
